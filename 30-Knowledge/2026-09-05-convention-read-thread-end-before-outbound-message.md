## Read the end of the thread first

Before drafting or sending anything on the user's behalf (email, chat, a professional network message,
any channel), read the latest messages in that thread. The user works fast and in parallel and sometimes
asks for something they have just done themselves. A message was once drafted asking a third party for a
document the user had already requested in the same thread minutes earlier; the duplicate was caught only
because the thread was opened first. Opening the thread also surfaces recent replies nobody has seen yet.

## Draft, show, then act

Sending mail, posting, replying, changing calendar events or publishing is visible to other people.
Draft it, show the user the exact text, and act only when the user says so in that exchange. An approval
covers that message or batch, never the next one.

## How it reads

- It sounds like the user: direct, friendly, brief, no corporate filler, no signature block unless the
  user uses one. [[2026-09-10-convention-write-like-a-person]]
- It is written in the recipient's or the thread's language.
  [[2026-09-15-convention-language-per-audience]]
- Nothing about a third party goes in unless it has been checked.
  [[2026-09-05-convention-verify-negative-claims-about-third-parties-before-writing]]
